# SCH-10 Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One page in `web/` that lists resources and bookings, books with a live availability preview, cancels, and shows every API answer, styled like `.design/prototype-html/Main.dc.html`.

**Architecture:** A client component (`BookingsPage`) owns all state and calls the API from the browser through `lib/api.ts` (`fetch`, `NEXT_PUBLIC_API_URL`, CORS on the API). Every decision that can be pure lives in `lib/bookings.ts` (validity, axis, result card, preview, optimistic reducer, log text) and is tested with `node --test`. Four presentational components render the prototype's panels.

**Tech Stack:** Next.js 16 (App Router, `cacheComponents`), React 19.3 (`useOptimistic`, `useTransition`), Tailwind 4, shadcn `base-nova` on `@base-ui/react`, Nest.js 11, Node 22.22 (`node --test` with type stripping).

**Spec:** `docs/superpowers/specs/2026-11-05-sch-10-web-ui-design.md`

## Global Constraints

- Read `web/AGENTS.md` first: this Next.js has breaking changes. Read `node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md` before writing a component.
- No new npm dependency. The shadcn CLI may copy component files only; if it wants to install a package, stop and ask. `npx npm@11 install` is the only way to add one (CLAUDE.md).
- The UI never computes overlaps and never sorts ids. Lists and `conflicts` render in API order.
- Error bodies use the key `error` (`{ error, message, conflicts? }`), not `code`.
- Words on screen: Interval, Canceled, "Preview: available", "Preview: conflict". Never "Cancelled" or "Period". A Canceled row's Action cell is empty.
- `api/openapi.yaml` does not change.
- Commits are conventional and end with `(SCH-10)`, plus the `Co-Authored-By` trailer.
- Run commands from the repo root unless a step says `web/`. The API needs Postgres (`docker compose up -d db`).

## Review Focus

1. **Stale preview:** typing `19` then `21` quickly fires two availability calls. A late answer for the first must not overwrite the second. Sequence guard in Task 6; checked in the browser with throttling.
2. **`id_taken` ghost row:** booking an id that already exists puts a ghost next to the real row with the same `id`. React keys must not collide (`key={`${b.pending ?? 'row'}:${b.id}`}`). Browser check in Task 5.
3. **Non-JSON or 5xx reply** (Nest's 400 body, an HTML error page): `call()` must not throw. The card shows "Request failed" with the status and raw text. Tests in Task 2.
4. **API dies mid-session:** the write and the re-fetch both fail. The card shows "Request failed", and the list keeps its last good value instead of switching to the load-failure panel. Rule in Task 5.
5. **Start = end** (`20`/`20`): Book stays enabled and returns `invalid_data`. The preview answers 422, so it reads "Couldn't check availability". Tests in Task 2.

```ts
// bookings.ts: no imports at all (Node runs it directly)
export type Resource = { id: string; name: string };
export type BookingStatus = 'active' | 'canceled';
export type Booking = { id: string; resource: Resource; start: number; end: number; status: BookingStatus };
export type ShownBooking = Booking & { pending?: 'add' | 'cancel' };
export type ApiReply = { status: number; body: unknown; raw: string } | { status: null; error: string };
export type Tone = 'ok' | 'error' | 'warning';
export type ResultCard = { tone: Tone; title: string; detail: string; code: string };
export type Preview = { tone: 'idle' | 'available' | 'conflict' | 'failed'; text: string; conflicts: string[] };
export type OptimisticChange = { kind: 'add'; booking: Booking } | { kind: 'cancel'; id: string };
export type BookRequest = { id: string; resource: string; start: number; end: number };

export function formatInterval(start: number, end: number): string;            // "[10,20)"
export function isBookable(start: string, end: string): boolean;               // both /^\d+$/ and 0..100
export function axis(ends: number[]): { max: number; ticks: number[] };
export function position(x: number, max: number): number;                      // percent, x / max * 100
export function bookResult(reply: ApiReply, req: BookRequest): ResultCard;
export function cancelResult(reply: ApiReply, id: string): ResultCard;
export function previewOf(reply: ApiReply | null, resource: string, start: number, end: number): Preview;
export function applyOptimistic(list: ShownBooking[], change: OptimisticChange): ShownBooking[];
export function describeCall(method: string, path: string, body?: unknown): string;   // `POST /bookings {"id":"C",...}`
export function describeReply(reply: ApiReply): string;                        // `409 {...raw}` or `request failed: <error>`

// api.ts: imports types only (`import type ... from './bookings'`)
export const API_URL: string; // process.env.NEXT_PUBLIC_API_URL ?? 'http://localhost:3001' (direct access, so Next inlines it)
export function call(method: 'GET' | 'POST', path: string, body?: unknown): Promise<ApiReply>;
```

  - `bookResult`:
    - 201 with body `{ id:'D', resource:{id:'R1',name:'Agora Room'}, start:19, end:21, status:'active' }` gives `{ tone:'ok', title:'Booking D created', detail:'R1 taken for [19,21).', code:'created' }`.

  - `cancelResult`:
    - 200 `{ result:'canceled', booking }` gives `{ tone:'ok', title:'Booking A canceled', detail:'Its id stays taken.', code:'canceled' }`.
    - 200 `already_canceled` gives `{ tone:'warning', title:'Booking A was already canceled', detail:'Nothing changed.', code:'already_canceled' }`.
    - 404 `not_found` gives `{ tone:'error', title:'Booking not found', code:'not_found' }`.
    - 200 with body `{}` gives `Request failed`.
  - `previewOf`:
    - `null` gives `{ tone:'idle', text:'Pick a start and an end from 0 to 100', conflicts:[] }`.
    - 200 `{available:true,conflicts:[]}` gives `text:'R1 [19,21) is available'`.
    - 200 `{available:false,conflicts:['B','A']}` gives `text:'R1 [19,21) conflicts with B, A'` and `conflicts:['B','A']`, in API order and never re-sorted.
    - 422 gives `{ tone:'failed', text:"Couldn't check availability" }`, and so does a network error.
  - `applyOptimistic`:
    - `add` appends the booking with `pending:'add'` and leaves the existing items unchanged, including one with the same id.
    - `cancel` of `A` gives that item `status:'canceled', pending:'cancel'` and leaves the others alone.
  - `describeCall('POST','/bookings',{id:'C'})` is `'POST /bookings {"id":"C"}'`, and `describeCall('POST','/bookings/A/cancel')` has no trailing body. `describeReply` gives `'409 <raw>'` and `'request failed: Failed to fetch'`.

    - A JSON 201 gives `{ status:201, body:<parsed>, raw:<text> }`.
    - A non-JSON 500 gives `body:null` and the raw text.
    - A rejected fetch gives `{ status:null, error:<message> }`.
    - It sends `content-type: application/json` and a JSON body only when `body` is given, to `${API_URL}${path}`.
