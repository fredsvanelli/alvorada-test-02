Implementation plan: `docs/superpowers/plans/2026-11-05-sch-10-web-ui.md` (design: `docs/superpowers/specs/2026-11-05-sch-10-web-ui-design.md`).

1. CORS on the API limited to `WEB_ORIGIN`; the web app calls the API from the browser at `NEXT_PUBLIC_API_URL` (default `http://localhost:3001`).
2. Pure helpers (`web/src/lib/bookings.ts`) and the API client (`web/src/lib/api.ts`), written test first and run with `node --test`.
3. The prototype's theme, IBM Plex fonts, and the shadcn Input, Table, Badge and Card.
4. The page loads resources and bookings: a timeline per resource and the bookings table with an Active / Canceled filter.
5. Book and Cancel with optimistic updates (50% opacity while pending), a result card and an operation log.
6. A live availability preview through `GET /availability` (250 ms debounce, latest answer wins). It replaces the Check button.
7. UI runbooks (fixtures recorded once, then replayed in mocked mode), and lint, typecheck, build and tests.

Departures from the issue are recorded in a separate comment.
