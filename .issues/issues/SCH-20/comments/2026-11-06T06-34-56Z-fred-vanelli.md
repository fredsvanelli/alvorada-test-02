## Implementation plan

**1. Shared dialog (refactor, no behavior change).** New `web/src/components/bookings/cancel-booking-dialog.tsx` exports `CancelBookingDialog({ booking, onCancel, trigger })`. It holds the dialog content now in `bookings-table.tsx`, unchanged: title "Cancel booking <id>?", "Keep booking" and "Cancel booking". The trigger goes to `AlertDialogTrigger render={trigger}`. The table uses it with its current Cancel button.

**2. The (x) on Timeline bars.** `Timeline` gets an `onCancel` prop from `BookingsPage`. A bar that is active and not pending renders the dialog after its label. The trigger is an 18px round button (`bg-white/20`, `bg-white/35` on hover) with a 12px white `XIcon`, labeled "Cancel booking <id> from the Timeline". It is `display: none` at rest and shows on bar hover (`group-hover:inline-flex`). The hover widening (`min-w-max`) fits the label plus the (x). Canceled bars, bars with a cancel in flight and newly booked bars still waiting for the API get no (x).

**3. Runbooks.** New `docs/runbooks/bookings/cancel-from-timeline.md` with `web/e2e/bookings/cancel-from-timeline.runbook.spec.ts`:
- S01: hovering an active bar shows the full label and the (x)
- S02: moving off the bar hides it
- S03: hovering a canceled bar shows no (x)
- S04: the (x) opens the same dialog
- S05: "Keep booking" sends nothing
- S06: Escape sends nothing
- S07: confirming turns the bar and the row Canceled, and the result card and the Operation log show the cancel

`view-home` S03 and S10 each get one line about the (x). `cancel-from-table` stays as it is and is re-run.

**4. Verify.** Run lint, typecheck, unit tests, build, `test:e2e` and `/runbooks:run --affected`, then `/utils:review-work` before the PR.

Out of scope: the API, keyboard and touch access to the (x).
