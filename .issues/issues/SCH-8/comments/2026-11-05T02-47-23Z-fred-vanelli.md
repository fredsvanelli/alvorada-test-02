## Note from SCH-7: two steps to add to the `bookings.check-availability` runbook

SCH-7 added `GET /availability` and the runbook `docs/runbooks/bookings/check-availability.md`. Two of its behaviors need endpoints that SCH-8 builds, so they are listed under "Not covered" there. When SCH-8 lands, run `/runbooks:update bookings.check-availability` and add:

1. **A check writes nothing:** create bookings, call `GET /availability`, then `GET /bookings` returns the same bookings, unchanged. (Today a unit test asserts the service never calls `insert`.)
2. **A canceled booking no longer conflicts:** with A R1 `[10,20)` canceled through `POST /bookings/A/cancel`, `GET /availability?resource=R1&start=10&end=20` returns `available: true, conflicts: []`.
