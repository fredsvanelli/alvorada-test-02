## Implementation plan

### Decisions from the grilling session

- `GLOSSARY.md` gains the term **Bookable window**. No ADR, because reversing this means changing one constant and its docs.
- One inclusive constant, `MAX_TIME = 100`, applies to `start` and `end`. `start < end` already rejects a `start` of 100.
- One service test proves that stored bookings still count: a stored `[90,130)` and a new `[95,100)` give `conflict`. List and cancel need no new test, because `parseInterval` runs only in create and availability.
- `maximum: 100` goes on the contract's `Time` schema, which only `CreateBookingRequest` uses. `Booking` gets no maximum, and gains one sentence about stored bookings.
- Runbook `bookings.view-home` uses B `[90,100)`. S04 gets a hand-written fixture with B `[90,130)` and opens the page itself.
- Fixtures are edited by hand, with their `source` lines updated, and compared once with curl against the running API.
- `bookings.view-home` stays without a script and runs in the browser.
- Tests replace the old boundary cases. The `2147483648` cases go away, because they take the same code path as 101.
- README decision 1 keeps the history and adds the SCH-16 change.
- The dated design docs in `docs/superpowers/` stay as they are.

### Steps

1. API rule, test first: `booking-rules.spec.ts`, `bookings.service.spec.ts`, `bookings.controller.spec.ts`, then `MAX_TIME` and both `invalid_data` messages.
2. API contract, in the same commit: `api/openapi.yaml`, then `npx @redocly/cli lint api/openapi.yaml`.
3. API runbooks, each runbook before its script: `create-booking` S15 and its table row for `end` 101, `check-availability` S05 row for `end=101` and a new S15 for `start=0&end=100`.
4. UI runbooks and fixtures: the four fixtures with the old message, `book-from-form`, `preview-availability`, the pinned message in `book-from-form.runbook.spec.ts`, and `view-home`.
5. Docs: `README.md`, `CLAUDE.md`, `docs/diagrams/architecture.md`.
6. Verify: `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`, `npm run test:e2e`, `/runbooks:list --affected`, `/runbooks:run --affected`, `/utils:review-work`.

### Known blocker

`bookings.view-home` can only be verified in a browser, and the Playwright MCP servers failed to connect in the session that wrote this plan.
