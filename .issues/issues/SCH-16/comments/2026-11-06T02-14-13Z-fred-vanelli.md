## Delivered in PR #16

https://github.com/fredsvanelli/alvorada-test-02/pull/16

`POST /bookings` and `GET /availability` now answer 422 `invalid_data` for a time above 100, and `start` 0 with `end` 100 is accepted. The contract, README, `CLAUDE.md`, architecture doc, glossary and runbooks state the new range.

### Changes from this issue's text

- **The web form changed, though this issue lists that as out of scope.** The review found the 100 written separately in the API and the form, and the author asked for it to be fixed in this branch. Both now read `MAX_TIME` from a new `config/` workspace. The form's behavior did not change.
- **Runbook `bookings.view-home` uses booking B at `[80,100)`**, not the `[90,100)` planned earlier, because a browser run showed the shorter bar clipped its text to `B [90,10`.
- **`create-booking` S03 also reads `GET /bookings`**, so this issue's second criterion is proven as written.

### Verification

Run locally before the commits, with CI still to run on the PR: `npm test`, lint, typecheck, build and `npm run test:e2e` pass, and all 10 affected runbooks pass. `bookings.view-home` ran in a headed browser, because the headless Playwright server did not reconnect in that session.
